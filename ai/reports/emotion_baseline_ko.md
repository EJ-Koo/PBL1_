# 감정 분류 베이스라인 보고서 — KcELECTRA × KOTE

- 프로젝트: 오늘의별일 (일기 감정 분석 → 행성 외형) · 작성일: 2026-10-14
- 학습: `ai/scripts/train_emotion_baseline.py` · 설정: `ai/configs/emotion_baseline.json` · 분석: `ai/notebooks/02_emotion_baseline.ipynb`
- 실행 ID: `baseline_v2021_s42` (가중치는 `ai/checkpoints/emotion_baseline/baseline_v2021_s42/`, Git 제외)
- 이 문서에는 집계 수치만 담았고, KOTE 원문과 실제 사용자 일기는 넣지 않았다.

## 1. 요약

| 항목 | 결과 |
|---|---|
| test macro-F1 (threshold 0.3, KOTE 논문 기준) | **0.557** |
| test macro-F1 (validation에서 정한 라벨별 threshold) | **0.567** |
| test micro-F1 / macro ROC-AUC | 0.642~0.648 / **0.871** |
| 참고: KOTE 공식 README macro-F1 | 0.56 (논문 버전) / 0.55 (HF Trainer 버전) |
| 행성 그룹(10개 + 없음) 단위 macro-F1 | **0.711** |
| 행성 기본색(주 그룹) 일치율 | top-1 **67.6%**, top-2 **85.8%** (무작위 12.5%) |

KOTE 공식 수치와 같은 수준의 베이스라인을 재현했다. 서비스 관점(행성 색)에서는 감정 그룹 단위로 대체로 맞는다. 다만 희소 감정은 약하다.

## 2. 학습 설정

| 항목 | 값 |
|---|---|
| 모델 | `beomi/KcELECTRA-base` tag `v2021` (124.6M 파라미터), [CLS] 위 분류 헤드 → 44개 시그모이드 |
| 데이터 | KOTE 공식 분할 train 40,000 / validation 5,000 / test 5,000, 공식 이진 라벨 |
| 입력 | 최소 전처리(공백 정리, HTML 엔티티 복원, 제어문자 치환), max_length 256 + 동적 패딩 (잘린 샘플 0) |
| 손실 | 라벨별 BCE |
| 최적화 | AdamW lr 2e-5, weight decay 0.01, linear warmup 10% (총 12,500 step 기준), grad clip 1.0 |
| 배치 | 실효 32 (= micro-batch 16 × 누적 2), gradient checkpointing, bf16 혼합 정밀도 |
| 모델 선택 | validation macro-F1@0.3 최고 epoch, 조기 종료 patience 3 |
| threshold | validation에서 결정(전체 공통 / 라벨별), test에는 그대로 적용 |
| 환경 | RTX 4060 Ti 8GB, PyTorch 2.14.1+cu130, transformers 5.19.0, Python 3.13.5, seed 42 |

KOTE 논문과 다른 점: 논문은 토큰 5% 무작위 교체와 5% 마스킹 증강, 512 고정 패딩을 썼다. 이 베이스라인은 증강 없이 256 동적 패딩을 썼다.

## 5. 라벨별 성능

- F1 범위는 0.22~0.83이다. 0.7 이상이 10개, 0.4 미만이 7개다.
- 상위: 불평/불만 0.83, 짜증 0.80, 화남/분노 0.79, 어이없음 0.78, 안타까움/실망 0.77
- 하위: 부끄러움 0.22, 죄책감 0.24, 귀찮음 0.27, 패배/자기혐오 0.30, 공포/무서움 0.31 (test 양성 84~306건)
- **라벨별 F1과 train 양성 수의 Spearman 상관은 0.89**다. 성능 차이의 대부분이 데이터 양으로 설명된다.
- 희소 라벨은 F1이 최대가 되는 threshold가 매우 낮다(죄책감 0.12, 부끄러움 0.13). ROC-AUC는 0.73~0.94로 순위 신호는 있으므로, 불균형 대응으로 개선할 여지가 있다.

## 7. 가상 일기 정성 점검

개발자가 쓴 가상 일기 12개(`ai/configs/demo_diaries.json`, 실제 사용자 일기 아님)로 확인했다. 수치 평가가 아니다.

| 기쁨+아쉬움 | 아쉬움·슬픔만 잡히고 즐거움은 놓침 |

## 8. 한계

1. **희소 감정 성능**: 부끄러움·죄책감 등 자기를 향한 부정 정서가 약하다. 일기에서는 중요할 수 있는 감정이다.
2. **도메인 차이**: KOTE는 온라인 댓글이다(부정·비판 비율이 높고 짧다). 일기 문체에서의 성능은 아직 검증하지 않았다.
3. **관대한 라벨**: 평가자 1명만 골라도 양성인 경우가 많아, 모델도 감정을 넓게 고른다(샘플당 예측 9.7개).
4. 단일 seed(42), 단일 실행 결과다. 실행 간 변동 폭은 측정하지 않았다.

## 9. 다음 단계

1. 희소 라벨 보강: 클래스 가중치 BCE 또는 focal loss → 라벨별 F1 비교
2. `raw.json`의 평가자 선택 수(0~5)를 soft label로 학습 → 감정 강도 표현 개선 기대
3. 동의를 받은 실제 일기 소량으로 도메인 검증, 필요하면 미세조정
4. seed를 바꾼 반복 실행으로 성능 변동 폭 확인
5. 백엔드 연동: `src/emotion/predict.py`의 `EmotionPredictor`를 FastAPI에서 호출
