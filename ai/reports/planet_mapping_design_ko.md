# 감정 → 행성 외형 매핑 설계 (초안 v0.1)

- 프로젝트: 오늘의별일 · 작성일: 2026-10-14
- 노트북: `ai/notebooks/03_planet_mapping.ipynb` · 설정: `ai/configs/planet_mapping.json` · 코드: `ai/src/emotion/planet_mapping.py`
- 상태: **설계 초안**. 색과 수치는 기획·프론트(3D)와 협의하고 사용자 검토를 거쳐 조정한다.

## 1. 설계 목표

일기 하나 → 행성 하나. 감정 분류 모델은 44개 감정 확률을 내지만, 44개를 각각 다른 색으로 보여 주면 사용자가 구분할 수 없다. 그래서 다음 세 가지를 목표로 했다.

1. **알아볼 수 있을 것**: 기본색만 보고도 그날의 큰 감정(기쁨·슬픔·분노 등)을 알 수 있어야 한다.
2. **섞인 감정도 표현할 것**: 일기는 감정이 하나가 아닌 경우가 많다(KOTE 샘플당 평균 7.9개). 보조색·고리로 복합 감정을 나타낸다.
3. **데이터 근거가 있을 것**: 감정 그룹은 KOTE의 실제 공존 패턴을 기준으로 만들고, 의미상 옮긴 라벨은 근거를 남긴다.

- 44개 라벨이 각각 정확히 한 곳에 배정되는지 코드로 검증한다(`validate_mapping`).

### 데이터 군집과 비교

KOTE train의 감정 공존 Jaccard 거리로 평균연결 계층 군집(k=10)을 만들면, 3개 이상 라벨을 가진 큰 덩어리 3개가 나온다.

| 데이터 덩어리 | 라벨 수 | 설계 그룹 |
|---|---:|---|
| 긍정 | 16 | 기쁨·즐거움, 감사·애정, 평온·안심, 기대·호기심 (4개로 세분) |
| 비판·분노 | 13 | 분노·불만, 혐오·불신 (+ 일부는 다른 그룹으로) |
| 슬픔 | 7 | 슬픔·상실 (+ 일부는 다른 그룹으로) |
| 단독 라벨 | 8 | 귀찮음, 부담/안_내킴, 비장함, 부끄러움, 공포/무서움, 없음, 죄책감, 재미없음 |

- 설계 그룹 10개 중 5개(기쁨·즐거움, 감사·애정, 평온·안심, 분노·불만, 혐오·불신)는 라벨 전부가 같은 데이터 덩어리 안에 있다.
- 의미 기준으로 옮긴 라벨과 근거:

| 라벨 | 데이터 덩어리 | 설계 그룹 | 근거 |
|---|---|---|---|
| 안타까움/실망 | 비판·분노 | 슬픔·상실 | 일기에서는 아쉬움·실망의 의미가 강함 |
| 당황/난처, 경악 | 비판·분노 | 불안·당황 | 각성이 높은 부정적 놀람 |
| 불안/걱정 | 슬픔 | 불안·당황 | 각성 수준이 슬픔과 다름 |
| 힘듦/지침 | 슬픔 | 지침·무기력 | 피로·소진이 중심 의미 |
| 패배/자기혐오 | 슬픔 | 부끄러움·자책 | 죄책감과 lift 8.6, 자기를 향한 부정 정서 |
| 비장함 | 단독(‘없음’과 가까움) | 기대·호기심 | 앞을 향한 결의 |

## 3. 행성 외형 규칙

| 행성 속성 | 계산 | 의도 |
|---|---|---|
| 기본색 `base_color` | 그룹 점수(그룹 내 라벨 확률의 최댓값)가 가장 높은 그룹의 색 | 그날의 대표 감정 |
| 보조색 `accent_color`, `accent_ratio` | 두 번째 그룹 색(점수 ≥ `secondary_min`). 비율 = 두 점수의 비 | 함께 느낀 감정 |
| 띠 `band_count` | 1 + round(4 × arousal) | 격한 감정일수록 띠가 많음 |
| 표면 소용돌이 `turbulence` | 활성 그룹의 arousal 가중 평균 | 격한 감정일수록 거친 표면 |
| 빛 번짐 `glow` | (valence+1)/2 × 대표 감정 점수 | 긍정적이고 강한 감정일수록 밝음 |
| 채도 `saturation` | 1 − 0.6 × P(없음), 최소 0.25 | 담담한 일기는 옅은 행성 |
| 고리 `ring` | 활성 그룹(점수 ≥ `active_min`)이 3개 이상이면 표시, 색은 세 번째 그룹 | 복합 감정 |
| 크기 `size_scale` | 0.85 ~ 1.15 × 대표 감정 점수 | 감정의 세기 |

설정값(`params`)은 `planet_mapping.json`에서 바꿀 수 있다. 코드를 고치지 않고 조정할 수 있도록 분리했다.

감정 모델(`baseline_v2021_s42`, 02 보고서)의 출력에 매핑을 적용했다. 파라미터 보정은 validation으로만 했고, test는 확인용으로만 썼다.

### 4.1 고리 기준 보정 (validation)

- 처음 값(0.5)에서는 행성 79%에 고리가 붙어 의미가 없었다. 기준에 가장 가까운 0.85로 정했다.

## 5. 프론트 전달 형식 (제안)

일기 저장 시 백엔드가 감정 모델 → 매핑을 실행하고 아래 JSON을 함께 저장해 프론트에 전달한다.

```json
{
  "mapping_version": "0.1-draft",
  "emotions": {
    "top": [{"label": "기쁨", "prob": 0.91}, "..."],
    "none_prob": 0.03,
    "groups": [{"id": "joy", "name": "기쁨·즐거움", "score": 0.91, "top_label": "기쁨", "active": true}, "..."]
  },
  "planet": {
    "base_color": "#FFD23F", "accent_color": "#FF8FB1", "accent_ratio": 0.45,
    "saturation": 0.98, "glow": 0.85, "turbulence": 0.6, "band_count": 3,
    "ring": {"visible": false, "color": null, "opacity": 0.0},
    "size_scale": 1.12, "valence": 0.85, "arousal": 0.6
  },
  "summary": "기쁨·즐거움 + 감사·애정"
}
```
(값은 형식 예시이며 실제 출력이 아니다.)

## 6. 한계와 협의가 필요한 점

1. **색 팔레트와 그룹 구성**: 현재 색은 초안이다. 특히 안타까움/실망을 슬픔에 넣은 판단은 데이터 군집과 다르므로 확인이 필요하다.
2. **크기 규칙**: 모델이 대표 감정에 거의 항상 0.9 이상을 주어 크기 차이가 거의 없다. 크기는 일기 길이·사진 수 같은 비감정 요소로 정하는 것을 제안한다.
3. **희소 감정의 색**: 부끄러움·자책, 지침·무기력은 기본색으로 거의 나오지 않는다. 데이터 자체에도 드물고(평가자 기준 0.9%, 4.6%), 모델의 해당 F1도 낮다(0.33, 0.60). 모델 개선(02 보고서 다음 단계)을 먼저 하고 다시 점검한다.
4. **파라미터 재보정**: `active_min` 등은 현재 모델 출력에 맞춘 값이다. 모델을 다시 학습하면 03 노트북 4절로 다시 보정한다.
5. **3D 표현**: 띠·소용돌이·고리·빛 번짐을 3D에서 어떻게 표현할지 프론트와 협의가 필요하다. 2D 미리보기는 설계 확인용일 뿐이다.
6. **사용자 체감 검증**: 실제 사용자가 자기 일기의 행성을 보고 감정이 잘 표현됐다고 느끼는지 확인하는 평가(소규모 사용자 테스트)가 필요하다.
