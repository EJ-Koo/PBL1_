# 행성 외형 v0.2: 감정 대표색·보조색·무늬·크기 규칙 (시안)

- 작성일: 2026-11-05 · 상태: **시안, 로컬에서만 확인** (운영 서버·앱에는 반영 안 됨, Git 커밋 전)
- 코드: `ai/src/emotion/planet_visual.py`, 설정: `ai/configs/planet_visual.json`
- 그룹 정의(어떤 라벨이 어느 그룹인지)는 바꾸지 않았다: `ai/configs/planet_mapping.json`
- 근거 수치: 서비스 모델 KcELECTRA(`baseline_v2021_s42`)의 KOTE validation/test 예측. 규칙은 validation으로 정하고 test로 확인했다.

## 1. 역할 분리

| 행성 속성 | 정하는 것 | 계산 위치 |
|---|---|---|
| 색·무늬·고리·대기광 | 감정 (모델 출력) | AI 서비스 `compute_visual` |
| 크기 | 일기 분량 (공백 제외 글자 수) | 프론트 `planetScaleForText` |
| 위치 | 일기 의미 (임베딩) | AI 서비스 좌표 (기존 그대로) |

감정 점수·사진 수는 크기에 쓰지 않는다. v0.1의 `size_scale`(감정 강도 → 크기)은 프론트에서 쓰지 않는다.

## 2. 데이터 흐름

```
일기 저장 → 백엔드 → AI /analyze → 모델 44개 확률 → compute_visual
          → stars.color = 대표색, stars.brightness = 0.5 + glow   (DB 스키마 변경 없음)
별 목록 GET /stars → 백엔드가 AI /analyze/batch로 행성 외형 계산(메모리 캐시) → 응답 planet 필드
          → 프론트 DiaryEntry.planet → 행성 셰이더
AI 서비스가 없거나 실패 → planet = null → 프론트는 저장된 대표색만(없으면 무채색 '분석 전' 행성)
```

## 3. 드문 감정의 색이 안 보이던 원인 (test 5,000개)

| 그룹 | 사람이 주 감정으로 고른 글에서 모델 판정 통과 | 판정된 글 중 v0.1 대표색 | v0.1 대표색·보조색 |
|---|---:|---:|---:|
| 부끄러움·자책 | 58% | 0.0% | 0.4% |
| 지침·무기력 | 80% | 3.2% | 14.2% |
| 평온·안심 | 86% | 12.4% | 29.1% |
| 불안·당황 | 91% | 9.6% | 24.9% |
| (참고) 분노·불만 | 96% | 49.8% | 73.0% |

- **대부분은 집계·선택 단계에서 묻혔다.** 모델은 드문 감정도 라벨별 기준값으로 판정하지만, v0.1은 대표색·보조색을 '확률 1·2위 그룹'으로만 골랐다. 드문 감정(부끄러움·지침·불안)은 확률이 낮게 나오고 기준값도 0.12~0.21로 낮아서, 판정은 되어도 흔한 감정(분노·호기심 등)이 늘 1·2위를 차지했다.
- **부끄러움·자책은 모델 예측도 약하다.** 사람이 주 감정으로 고른 글에서도 확률 평균 0.29(다른 그룹 0.56~0.88)였다. 이 부분은 시각화로 고칠 수 없다.
- 대표색 선택 방식을 바꾸는 것도 시험했다. 기준값 대비 여유로 고르면 주 그룹 일치율 68.2% → 68.0%, 기준값 비율로 고르면 57.5%로 떨어졌다. 그래서 **대표색은 확률 최댓값 그대로 두고, 보조색 규칙만 바꿨다.**

| 그룹 | 대표색 | v0.1 |
|---|---|---|

| 감사·애정 | `#FF9CC2` 연분홍 | `#FF8FB1` |
| 평온·안심 | `#3FCF8E` 초록 | `#5ED3A4` |
| 기대·호기심 | `#2EC4E8` 하늘 청록 | `#3EC6E0` |
| 분노·불만 | `#E5383B` 빨강 | 같음 |
| 혐오·불신 | `#8FA12A` 올리브 | `#7A8B2E` |
| 슬픔·상실 | `#3157E6` 파랑 | `#3A5BD9` |
| 불안·당황 | `#B888FF` 연보라 | `#8E5BD9` |
| 지침·무기력 | `#C0773A` 황갈색 | `#8C7B6B` (회갈색) |
| 부끄러움·자책 | `#9E2266` 자주 | `#A23B72` |
| 없음 | `#AEB4C0` 회청색 | `#B8BCC6` |

- v0.1은 지침(회갈색)이 '없음' 회색과 가깝고, 슬픔과 불안이 서로 가까웠다. 11개 색 사이 최소 거리(CIELAB ΔE76)는 19.9 → 32.8로 늘었다.
- 같은 그룹 안에서는 모델이 가장 높게 본 라벨에 따라 무늬색(`tone_color`)만 색상 ±7°·명도 ±0.05 바꾼다. 대표색은 그대로다.
- **표면 디자인 = 대표색 계열의 가는 구름층·광물층** (프론트 `planet-visual.ts`, `universe-scene.tsx`)
  - 디자인 변경 과정: 얼룩·점무늬(어수선함) → 원색 가로 띠(장난감처럼 보임) → 지금.
  - 팔레트: 행성마다 대표색 1개에서 4색을 만든다. 색상(hue)은 대표색 그대로 두고 명도·채도만 바꾼다(반대색을 만들지 않음).

    | 색 | 만드는 법 | 쓰는 곳 |
    |---|---|---|
    | 대표색 | 서버 `base_color` 그대로 | 표면 대부분(첫인상) |
    | 무늬색 | 서버 `tone_color`(같은 그룹, 라벨별 색상 ±7°) | 일부 층 |
    | 어두운 색 | 명도 ×0.66(노랑은 ×0.78, 주황 쪽으로 조금), 채도 ×0.85 | 가는 그늘 층 |
    | 밝은 색 | 명도를 흰색 쪽으로 40%, 채도 ×0.85(파랑은 하늘색 쪽으로 조금) | 구름·가장자리 대기·고리 |

    - 노랑을 어둡게 하면 갈색(지침 색)으로, 파랑을 밝게 하면 연보라(불안 색)로 보여서 이 두 경우만 색상을 조금 옮긴다.
  - 층 배치: 위도별로 여러 주기의 노이즈를 겹친 '층 값'이 가운데 넓은 구간이면 대표색, 높으면 무늬색·밝은 색, 낮으면 어두운 색이다. 셰이더가 이 색 줄을 노이즈로 두 번 휘게 해(도메인 워핑) 가는 층이 흐르는 결을 만든다.
  - 무늬 종류(각성)에 따라 층 대비, 휘는 정도, 소용돌이 세기, 구름 양을 바꾼다. 소용돌이는 중위도 한 곳에만, 절반 정도의 행성에서는 약하게 둔다.
  - 보조 감정: 색상은 그대로 두고 채도를 낮추고(0.4 아래로는 내리지 않음) 명도를 대표색 근처로 모은 색이다. 중위도 한 구역 안에 가는 층으로 들어가고, 실제 면적은 weight × 0.65이다.
    - 반투명으로 섞으면 파랑 위 황갈색처럼 반대에 가까운 색이 회색('없음'처럼 보임)이 되어서, 거의 불투명하게 그리고 면적을 줄였다.
    - 구에서 위도 띠의 면적은 높이 구간 길이에 비례하므로(아르키메데스) 면적을 정확히 맞출 수 있다. 어느 쪽에서 봐도 모든 위도가 보여서 보조 감정이 돌려 보는 면에 따라 사라지지 않는다.
  - 조명: 화면 기준 오른쪽 위에서 옆으로 비스듬히 오는 빛 하나. 빛 받는 면은 부드럽게 밝고, 왼쪽 아래 가장자리에 어두운 면이 보여 둥근 형태가 드러난다. 어두운 면에도 반대쪽 약한 반사광(표면색의 7~13%)이 있어 색이 조금 보인다. 가장자리로 갈수록 조금 어둡게(림 감쇠) 하고, 하이라이트는 넓고 약하게만 넣는다.
    - 행성마다 전체 밝기를 0.9~1.1배로 조금 다르게 한다(서버 밝기 값). 색상은 바꾸지 않는다.
  - 대기광: 대표색 계열 밝은 색과 대표색을 섞은 색. 표면 가장자리 몇 픽셀(빛 받는 쪽 위주) + 1.05배 반지름의 얇은 바깥 막. 세기는 행성마다 다르다(0.3 + 0.5 × 서버 glow + 일기별 고정 난수 0~0.15, '없음'은 약하게). 저품질에서는 바깥 막을 뺀다.
    - 바깥 막은 색만 더하고 캔버스 알파는 바꾸지 않는다(덧셈 혼합이 알파까지 더하면 투명 캔버스에서 행성 둘레가 검은 테두리로 보였다).
  - 선택(웹: 마우스 올림, 휴대폰: 누름): 그 행성만 약 18% 밝게, 채도 +15%, 가장자리 빛과 바깥 막을 더 밝게, 화면에서 6% 크게. 다른 행성은 25% 어둡게. 약 0.3초에 걸쳐 켜지고 꺼진다. 전체 화면 Bloom은 쓰지 않는다.
    - 겹쳐 있으면 카메라에 가장 가까운 행성만 선택한다. 누른 강조는 0.7초 뒤 꺼진다(누르면 지금처럼 일기 화면이 열린다).
    - 웹 마우스 올림은 r3f native 이벤트가 전달하지 않아, 마우스 이동을 직접 받아 카메라 광선으로 행성을 고른다(한 프레임에 한 번).
  - 움직임: 자전은 한 바퀴 약 90~210초(행성마다 다름). 카메라는 사용자가 돌리거나 확대할 때만 움직인다. 배경 별은 PC 500·휴대폰 350·저품질 250개로, 대부분 작고 어둡고 소수만 크고 밝다. 색온도를 조금씩 다르게 하고 반짝임은 넣지 않는다.
  - 고리: 서버 규칙(뚜렷한 복합 감정)인 행성에만, 적도면에 둔다. 반지름 1.35~2.15배에 주기가 다른 가는 고리 여러 겹과 빈 틈 하나가 있고, 행성 그림자가 진다. 색은 대표색 계열 밝은 색이고, 두 번째 보조 감정 색이 조금 섞인다. 자전축을 13~20도만 기울여 정면에서 얇은 타원으로 보이고, 행성 앞쪽은 행성 위를, 뒤쪽은 행성 뒤를 지나간다.
  - 확인(시험 일기, 이 PC 화면 캡처): 행성 빛 받는 쪽 픽셀 평균색이 가장 가까운 대표색이 그 일기의 대표 감정 색인지 봤다. 7개(감정 6 + 없음) 비교 화면에서 7/7, 15개 격자에서 평균색 10/15, 픽셀 다수결 12/15, 색상 계열 다수결 14/15였다. 틀린 것은 큰 보조 감정이 있는 파랑 행성(평균이 섞여 연보라·회색 쪽), 채도를 낮춘 soft 상태 행성, 분홍과 자주처럼 색상이 가까운 경우다.
- 층 배치·소용돌이 위치·자전축 기울기·자전 속도는 일기 id로 정한 고정 난수다. 감정과 무관한 변화라서 같은 감정의 행성이 똑같이 반복되어 보이지 않게 하는 데만 쓴다.

## 5. 계산 과정: 모델 출력 → 그룹 점수 → 행성 색

1. **모델 출력**: 44개 라벨 확률 p. 라벨별 판정 기준값 t는 validation에서 정한 값(`thresholds.json`)이다. p ≥ t이면 '판정'한 것이다.
2. **그룹 점수**
   - 강도 = 그룹 안 라벨 확률의 최댓값
   - 여유 = 그룹 안 (logit p − logit t)의 최댓값
   - 판정 = 그룹 안 라벨이 하나라도 p ≥ t
3. **상태**

| 상태 | 조건 | 표시 | test 비율 |
|---|---|---|---:|
| clear | 주 그룹 강도 ≥ 0.7 | 대표색 그대로, 보조 최대 2 + 드문 감정 1 | 95.5% |
| soft | 0.5 ≤ 강도 < 0.7 | 채도 70%, 보조 1 + 드문 감정 1 | 0.9% |
| muted (애매) | 강도 < 0.5 | 대표색을 회청색 쪽으로 70% 섞음, 보조 없음 | 0% |
| muted (근거 없음) | 어떤 감정도 기준값 미만 | 감정 색 없이 회청색 | 0% |
| none (없음) | '없음' 판정 & p(없음) ≥ 주 그룹 강도 | 회청색 기본 행성. 판정된 감정은 옅은 층(≤15%)으로만 | 3.6% |

   - 0.5·0.7 기준: validation에서 주 그룹이 공식 라벨에 있는 비율은 강도 0.7 미만 약 0.65~0.70, 0.7 이상 0.80~0.98이었다. 0.5 미만은 23개뿐이라 근거가 약하다. 댓글보다 애매한 글이 많을 일기에서 다시 정한다.
   - '없음'은 부정 감정으로 취급하지 않는다. 'none' 조건에 맞는 글 중 사람 투표에서도 '없음'이 우세한 비율은 약 55%였다.
4. **보조 감정**: 판정을 통과한 다른 그룹만 쓴다. 모델이 판정하지 않은 감정은 보조색으로도 만들지 않는다.
   - ① 여유가 큰 순서로 2자리(soft는 1자리). 면적은 최대 26%·12%이고, 보조 점수/주 점수 비율만큼 작아진다.
   - ② 남은 판정 그룹 중 KOTE train에서 가장 드문 그룹 1자리. 면적 3.5~7%(화면에서는 그 65%).
   - 주 그룹 색은 항상 55% 이상이다.
5. **장식** (모든 행성에 붙이지 않음)
   - 고리 = 뚜렷한 복합 감정: clear이고 보조 ①이 2개이며 두 번째 강도 ≥ 0.85. validation 14.6%, test 15.3%.
   - 대기광 = 밝은 감정: clear이고 glow ≥ 0.6. test 36.6%, 대부분 긍정 감정.
   - 무늬 종류 = 주 그룹 각성. 높음 → 소용돌이(층이 크게 휘고 소용돌이가 강함), 중간 → 띠, 낮음 → 부드러운 결, 없음·애매 → 옅은 안개(층 대비 작음).
6. **밝기**: glow = (쾌 + 1)/2 × 주 그룹 강도 (none은 0, muted는 절반). stars.brightness = 0.5 + glow. 프론트 발광은 약하게만 더해서 대표색이 하얗게 날아가지 않게 했다.

- 판정된 감정이 화면에 더 많이 나타나는 대신, 보조색의 정답률은 떨어졌다. 특히 부끄러움·자책은 0.28이다.
- 그래서 정답률이 낮은 자리일수록 면적을 작게 그린다(드문 감정 자리 3.5~7%).

## 6. 크기 (일기 분량)

- 배율 = 0.8 + 0.5 × log(1 + n/50) / log(1 + 600/50), n = 공백 제외 글자 수(600자에서 최대)
- 예: 0자 0.80 · 50자 0.94 · 200자 1.11 · 600자 이상 1.30 (기본 반지름 0.3에 곱함)
- 일기를 수정하면 프론트가 바뀐 본문으로 바로 다시 계산한다(`diary-context.tsx`의 `updateEntry`가 text를 바꿈).
- 백엔드 `stars.size`는 예전 규칙(공백 포함 글자 수, 0.25~1.2)으로 계속 저장되고, 수정할 때도 `update_diary`에서 다시 계산된다. 다만 프론트는 이 값을 쓰지 않는다. 규칙을 하나로 맞출지는 팀과 정한다.

## 7. 렌더링 비용과 품질 설정

| 품질 | 구 분할 | 노이즈 겹 | 대기광 | 자동 선택 |
|---|---|---|---|---|
| low | 20 | 2 | 끔 | 행성 150개 초과 |
| medium | 32 | 3 | 켬 | 모바일·폭 600 미만·행성 60개 초과 |
| high | 48 | 4 | 켬 | 그 외(PC 웹) |

- 행성 하나당 그리기 호출은 본체 1번에, 고리·대기광이 있으면 각각 1번 더 한다.
- 픽셀당 노이즈 계산은 (겹 수 × 2 + 1)번이다(medium 7번). 행성 하나당 그리기 호출은 본체 1 + 바깥 대기막 1(low 제외) + 고리 1(있을 때). 층 색은 행성마다 512×1 텍스처 한 장(2KB)으로, 계단 현상을 줄이려고 세 번 읽는다.
- `EXPO_PUBLIC_PLANET_QUALITY=low|medium|high`로 품질을 고정할 수 있다.
- 측정은 이 PC(RTX 4060 Ti) 헤드리스 크롬에서만 했다. 행성 15·60·150·250개(60개 초과 medium, 150개 초과 low)에서 PC·휴대폰 크기 모두 화면 갱신 상한(측정 당시 다른 프로그램 때문에 32fps)에서 떨어지지 않았고 셰이더 오류는 없었다. **실제 휴대폰에서는 측정하지 않았다.**
