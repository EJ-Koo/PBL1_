## 2. 데이터: KOTE (한국어 온라인 댓글 감정 데이터셋)

- 출처: Jeon et al. (2022), arXiv:2205.05300, MIT 라이선스
- 규모: 댓글 50,000개(train 40,000 / validation 5,000 / test 5,000), 감정 43개 + ‘없음’ = 44개 라벨, 다중 라벨
- 공식 출처에서 고정 버전으로 내려받고 SHA-256으로 검증했다.
- 품질: 결측·잘못된 라벨 0건, 분할 사이 근접 중복 1쌍
- 원시 주석(평가자 5명) → 배포 라벨 변환 규칙(논문 4.4절)을 50,000건 전부 재현해 확인했다.
- 특징: 샘플당 평균 7.9개 라벨로 넓게 붙어 있고(평가자 1명만 골라도 양성인 경우가 많음), 라벨 빈도 차이가 최대 약 25배다.
- 입력 길이: KcELECTRA 토큰 기준 최대 237 → max_length 256이면 잘리는 샘플이 0이다.
- 상세: `ai/reports/kote_analysis_ko.md`

## 3. 감정 분류 베이스라인

| 항목 | 결과 |
|---|---|
| 모델 | KcELECTRA-base(v2021, 124.6M), 44개 다중 라벨 분류 |
| 학습 | RTX 4060 Ti, 약 50분, 9 epoch(조기 종료, 6 epoch 모델 선택) |
| **test macro-F1** | **0.557** (threshold 0.3) / **0.567** (라벨별 threshold, validation에서 결정) |
| test micro-F1 / macro ROC-AUC | 0.64 / 0.871 |
| 참고: KOTE 공식 수치 | macro-F1 0.56 (논문) / 0.55 (HF Trainer) → **같은 수준으로 재현** |
| 행성 그룹(10개 + 없음) 단위 macro-F1 | **0.711** |
| 행성 기본색 일치율 | top-1 **67.6%**, top-2 **85.8%** (평가자 투표 기준, 무작위 12.5%) |

- 잘 맞히는 감정: 불평/불만 0.83, 짜증 0.80, 화남/분노 0.79, 즐거움/신남 0.76 (F1)
- 약한 감정: 부끄러움 0.22, 죄책감 0.24, 귀찮음 0.27, 패배/자기혐오 0.30 → 모두 희소 라벨이다(F1과 학습 데이터 양의 상관 ρ = 0.89).
- 상세: `ai/reports/emotion_baseline_ko.md`, `ai/notebooks/02_emotion_baseline.ipynb`

## 4. 감정 → 행성 외형 매핑 (설계 초안 v0.1)

- **44개 감정 → 10개 감정 그룹 + ‘없음’**: KOTE 감정 공존 데이터의 군집(긍정 / 비판·분노 / 슬픔 덩어리)을 경계로 삼고, 의미 기준으로 세분했다. 10개 중 5개 그룹은 데이터 군집과 완전히 일치한다.
- 그룹: 기쁨·즐거움, 감사·애정, 평온·안심, 기대·호기심, 분노·불만, 혐오·불신, 슬픔·상실, 불안·당황, 지침·무기력, 부끄러움·자책

| 행성 속성 | 감정과의 연결 |
|---|---|
| 기본색 / 보조색 띠 | 1순위 / 2순위 감정 그룹 |
| 빛 번짐 | 긍정적이고 강한 감정일수록 밝음 |
| 표면 소용돌이·띠 수 | 격한(각성이 높은) 감정일수록 거침 |
| 채도 | ‘없음’이 높을수록 옅음 (담담한 일기) |
| 고리 | 뚜렷한 복합 감정(3개 그룹 이상) |

- 실제 모델 출력에 적용해 점검했다. 고리 기준을 평가자 기준(validation 12.4%)에 맞추니, test에서 고리 비율 14.5%(평가자 기준 13.4%)가 나왔다.
- 가상 일기 12개 미리보기: 기쁨·기대·분노·슬픔·불안·지침은 의도한 색으로 나온다. 자책 일기는 슬픔 색으로 나온다(희소 감정 한계).
- 프론트에 넘길 JSON 형식을 제안했다(`ai/reports/planet_mapping_design_ko.md` 5절).
- 상세: `ai/reports/planet_mapping_design_ko.md`, `ai/notebooks/03_planet_mapping.ipynb`

## 5. 발견한 문제와 대응

| 문제 | 대응 / 계획 |
|---|---|
| 희소 감정(부끄러움·죄책감 등) 성능 낮음 | 클래스 가중치·focal loss, 원시 주석 soft label 실험 예정 |
| KOTE는 댓글, 서비스는 일기 (도메인 차이) | 동의받은 실제 일기 소량으로 검증 필요 |
| 감정 강도로는 행성 크기가 거의 같게 나옴 | 크기는 일기 길이·사진 수 등 다른 요소로 정하는 방안 제안 |
| 모델이 감정을 넓게 고름(정답 7.9개 vs 예측 9.7개) | 라벨별 threshold 적용, soft label 실험으로 완화 시도 |

## 6. 확인받고 싶은 사항

1. 베이스라인 성능(macro-F1 0.567, 그룹 단위 0.711)을 1차 모델로 써도 될지, 아니면 희소 감정 개선을 먼저 할지
2. 감정 그룹 10개 구성과 색 설계 방향(특히 ‘안타까움/실망’을 슬픔 그룹으로 배정한 판단)
3. 실제 일기 검증 방법: 팀원·지인의 동의를 받은 일기를 소량 쓸 수 있는지, 그 경우 개인정보 처리 방식
4. 다음 단계 우선순위: (a) 감정 모델 개선, (b) 의미 임베딩(BGE-M3)·별자리 연결, (c) 백엔드(FastAPI) 연동
