# Frontend 변경 기록

목업(`mockup/`)에 다른 브랜치의 프론트 작업을 합치면서 생긴 변경사항 기록.
원본 코드를 고친 게 아니라 **목업 쪽 사본에만 반영**했으므로, 원본 브랜치(`front`,
`back_end_wodnjs`)에도 같은 수정이 필요하면 이 문서를 보고 직접 옮겨 적용할 것.

---

## 2026-09-29 — 3D 우주 홈 화면 이식 + 웹 드래그 버그 수정

**베이스**: `back_end_wodnjs` 브랜치의 `mockup/`(로그인이 이미 실제 백엔드와 연동된 버전)

**가져온 원본**: `front` 브랜치의 `frontend/src/app/index.jsx`
(react-three-fiber로 만든 3D 우주 + 별 + Quest 모달)

### 1. 구조 변경
- `mockup/src/app/index.tsx`의 `UniversePage`: 평면 3열 그리드(FlatList) → 3D 우주 렌더링으로 교체
- `mockup/src/components/universe-scene.tsx`: **신규 파일**. `frontend/index.jsx` 안에 섞여있던
  `FloatingStar`/`UniverseScene` 로직을 분리해서 재사용 가능하게 정리

### 2. 버그 수정 — 원본에 있던 문제
**증상**: 원본(`frontend/index.jsx`)의 드래그 회전 로직은 `<View onStartShouldSetResponder
onResponderMove>` (React Native 구식 터치 전용 API)를 사용. 이 방식은 **모바일 터치에서는
동작하지만 웹 브라우저의 마우스 드래그는 못 받음.**

**원인 진단 과정**:
1. `onResponderMove` → 웹에서 안 됨 확인
2. W3C `onPointerDown`/`onPointerMove`(View에 부착)로 교체 → 여전히 웹에서 안 됨
   (View가 감싸는 방식 자체가 react-three-fiber 캔버스와 조합했을 때 이벤트가 안 올라옴)
3. **최종 해결**: react-three-fiber 자체 포인터 이벤트 시스템 사용 — 씬 안에 투명한
   `DragPlane`(평면 메쉬)을 두고 거기서 `onPointerDown/Move/Up`을 받음. 별 클릭(`onClick`)이
   이미 이 방식으로 잘 동작하고 있어서 동일한 방식으로 통일함.
4. 헤드리스 브라우저(Playwright)로 마우스 드래그를 흉내 내서 별 위치가 실제로 바뀌는 것까지
   확인함.

**결론**: `front` 브랜치의 원본 `frontend/index.jsx`를 웹에서 그대로 돌려도 마우스 드래그는
안 될 것으로 예상됨. 웹 지원이 필요하면 원본에도 3번 방식 적용 필요.

### 3. UI 변경
- 상단 우측 "Quest" 버튼 → **"커뮤니티"로 이름만 변경**. 안쪽 모달 내용은 아직 원본 퀘스트
  패널(진행률 바 포함) 그대로 — 실제 커뮤니티 기능 내용은 미정이라 확정되면 통째로 교체 필요
- 별 클릭 시 `/planet/[id]` 상세 페이지로 이동하도록 연결 (원본엔 없던 기능, 목업의 기존
  라우팅 구조에 맞춰 추가)
- 일기 작성 버튼(`+`)은 원본의 화면 내 인라인 폼 대신, 목업에 이미 있던 `/write` 화면
  (사진 첨부·공개범위 설정 가능)으로 연결

### 4. 의존성 추가 (`package.json`)
Expo SDK 57 호환 버전으로 고정 설치함:
- `three@0.186.1`, `@react-three/fiber@9.8.1`
- `expo-gl@57.0.2`, `expo-asset@12.0.13`, `expo-file-system@57.0.7`
- `@types/three` (devDependency)

### 5. 검증한 것 / 못한 것
- ✅ `npx tsc --noEmit` 통과
- ✅ 헤드리스 브라우저로 3D 렌더링 + 드래그 회전 직접 확인
- ⚠️ `npx expo lint`는 컨테이너 네트워크 제약으로 실행 못 함 (코드 문제 아님)
- ⚠️ Expo Go 앱(모바일)에서는 네이티브 모듈(`expo-gl` 등) 로드 실패로 에러 발생 확인됨
  → 웹 배포 또는 EAS 개발 빌드로는 해결되는 문제로 확인 (Expo Go 자체의 한계)

### 6. 아직 로컬 상태만 사용 중 (서버 연동 안 됨)
- 일기 생성(`+`)/조회가 `POST /diaries`, `GET /diaries`를 호출하지 않고 React state에만 저장됨
  → 새로고침하면 사라짐. 다음 작업으로 예정.
- 일기 수정: 백엔드에 PUT 엔드포인트 자체가 없어서 보류 (백엔드 쪽 작업 필요)

## 2026-09-29 (2차) — 퀘스트/커뮤니티 라벨 교체 + 오른쪽 탭 페이지 이동

**배경**: 실기기 테스트 중 라벨이 서로 바뀌어 있는 게 확인됨 — 우주 화면 우상단 버튼(눌렀을 때
진행률 바 있는 패널이 뜸)은 원래 "퀘스트"인데 "커뮤니티"로 잘못 표기되어 있었고, 페이저의 세
번째 페이지(현재는 빈 placeholder)는 원래 "커뮤니티"인데 "퀘스트"로 표기되어 있었음.

### 변경 내용 (`mockup/src/app/index.tsx`)
- `PAGE_LABELS` 배열: `'퀘스트'` → `'커뮤니티'`
- 페이저 3번째 페이지 `<PlaceholderPage label="퀘스트" />` → `label="커뮤니티"`
- 우주 화면 우상단 버튼 텍스트: `커뮤니티` → `퀘스트` (원래대로 복구)
- 퀘스트 모달 제목: `커뮤니티` → `퀘스트` (원래대로 복구)
- **신규**: 스와이프 외에, 화면 오른쪽 가장자리(중간 구간, 상단 퀘스트 버튼/하단 FAB와 안 겹치는
  영역)를 탭하면 다음 페이지로 넘어가는 `nextZone` 투명 버튼 추가 (`goToPage(pageIndex + 1)` 재사용).
  마지막 페이지에서는 표시 안 함. 일단 "오른쪽 탭 = 다음 페이지"만 구현한 1차 버전 — 왼쪽 탭으로
  이전 페이지 이동은 아직 없음.

### 확인된 것 / 안 한 것
- ✅ `npx tsc --noEmit` 통과
- ⚠️ 헤드리스 브라우저로 직접 재검증은 안 함 (텍스트/레이아웃 변경 위주라 위험도 낮다고 판단) —
  실기기/웹에서 눌러서 확인 필요
- 모바일 꾹 눌러서 별 생성하는 기능은 이번에도 미구현 (기존에 안 급하다고 확인됨)
